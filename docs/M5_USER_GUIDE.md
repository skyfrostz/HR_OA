# M5 请假与审批操作说明

本说明对应 [M5 API 契约](M5_API_CONTRACT.md)，实际验证范围见 [M5 验证记录](VALIDATION_M5.md)。所有示例均使用开发测试资料。

## 先配置再申请

HR 管理员维护请假类型、工作日历、年度额度和审批规则。默认工作日为周一至周五；需要自行录入调休工作日、休息日等日期例外。系统没有内置法定节假日或自动推算的法定年假，也不自动跨年结转。

年度额度分为四个量：人工已用是原台账中登记的基线；审批已用是新版请假最终批准后产生的使用量；预占是进行中申请占用的额度；可用额度等于总额度减去前三项。修改人工台账不能抹掉审批使用或预占，也不能使可用额度变负。

所有扣额度类型共用员工的年度年假台账，本轮不提供每个假种独立的余额池。非额度假不扣年度余额，仍受工作日历、半天区间和时间重叠检查约束。停用类型只阻止以后的新申请；已有申请保留提交时的类型、日历和计算结果。

## 发起请假

在 PC 或 H5 选择请假类型、起止日期及上午/下午，填写原因后预览。日期首尾包含在内，同日的上午至上午或下午至下午为半天，上午至下午为一天；系统跳过非工作日。跨年的申请按每个实际工作日期所属年度分别占用额度。

核对工作半天数、年度分摊和余额，再提交。日期或类型变更后需要重新预览；若管理员在此期间修改了类型或日历，提交会提示重新预览。预览不会锁住余额，另一笔申请可能先占用额度，提交时服务端会再次检查余额和重叠。

新申请采用提交时匹配的顺序规则。优先级数字较大的规则优先；部门只匹配员工直属部门，报销金额按分计算、包含上下界。没有匹配规则时使用演示默认路径。修改规则不会改变正在审批或已经结束的申请。

## 审批与额度变动

| 操作 | 可操作人和条件 | 额度变化 |
| --- | --- | --- |
| 提交 | 有员工绑定的申请人，计算和余额校验通过 | 按年度预占 |
| 最终批准 | 当前有效审批人 | 预占转为审批已用 |
| 驳回 | 当前有效审批人 | 释放预占 |
| 撤回 | 申请人本人，申请仍在进行中，填写原因 | 释放预占并关闭当前任务 |
| 撤销已批请假 | HR 管理员，新版已批准请假，填写原因 | 按原计算快照冲回审批已用 |

中间节点批准不会再次预占或提前扣减。非额度假没有额度流水。已拒绝、撤回或撤销的请假不再占用时间；驳回后可重提，其他情况可重新发起，均使用当前配置重新预览和计算。

员工可查看本人余额和流水。流水保留预占、消费、释放和冲回事件，以及关联申请，不通过删除原流水表示撤销。人工基线的变更仍从年度台账和业务变更历史核对。

M1–M4 历史请假没有新版计算快照，仍可查看和处理，但不会追溯扣款，也不参与新版半天占用判断；历史申请重提时需要补齐新表单。管理员的已批请假列表只提供处理所需摘要，不因此获得所有申请的私人理由或完整表单。

## 催办与异常处理

申请人可催办本人进行中的申请，每次成功催办至少间隔五分钟。通知只发送给当前有效处理人；重复提交同一幂等操作不会重复投递。当前投递为本地模拟通知，不是企业微信消息。

管理员在异常列表检查当前或未来审批人不可用的流程，选择有效接手人并填写原因。未来步骤的交接保留原路径和时间线，接手人实际取得任务后才获得通知和申请访问权。正常离职办理仍使用原有账号交接流程。

工作台数字来自同权限的业务列表，可进入待办、本人申请、合同提醒以及管理员异常处理等入口。未分配任务、无员工绑定或无权查看的内容，不通过工作台绕过原访问限制。

## 重试和业务边界

提交后若连接中断或结果未知，保留当前页面的待确认操作并按提示重试、刷新核对；不要把未知结果当作失败连续新建。服务器使用幂等记录和事务避免同一操作重复生效。页面切换、登出与浏览器刷新仍遵循现有内存会话机制。

正式额度、节假日和审批人员应由实际业务方确认。本轮不含自动法定额度、复杂分支/会签、真实企业微信或 OSS 联调、电子签章及生产部署。
