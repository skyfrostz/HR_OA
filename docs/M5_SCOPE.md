## 本轮交付

1. 请假类型、工作日历、半天与跨年计算：管理员配置年假/非额度假类型及周规则、日期例外；申请前可预览实际工作半天和年度分摊，服务端提交时重算并存快照。演示默认周一至周五工作，日期例外由管理员配置，不假定法定假期已导入。年度余额按实际请假日期所属年拆分；不自动结转或推算法定额度。
2. 年假余额流水与审批联动：使用现有人工年度额度作为基线，保留既有已用记录；新申请预占、最终批准扣减、驳回/撤回释放，管理员撤销已批准请假按原快照冲回。保留不可变流水和关联申请，禁止删除旧流水或凭空追记旧申请。处理重叠、余额不足和并发；原人工维护不能抹掉审批产生的使用量或预占。
3. 有版本的顺序审批规则：管理员按申请类型、部门范围及报销金额选择顺序审批人，明确规则优先级和默认路径。配置生效只影响新申请，既有申请保留规则/路由快照；服务端阻止无效账号、自审批和歧义，沿用 M4 交接解析。采用受限表单配置，不引入分支/会签设计器。
4. 撤回、撤销、催办与异常处理：申请人可撤回进行中申请；HR_ADMIN 可带原因撤销已批准的新版请假并冲回余额，普通员工不能直接修改已批准结果。进行中申请人催办当前有效处理人，服务端限频、幂等、审计和 outbox，仍只模拟通知。后台检测不可用处理人，管理员可检查并交接异常任务，保留原快照与完整记录；既有 M4 正常离职交接继续有效。
5. 真实工作台：按角色返回待办/本人申请/合同到期/异常等授权计数与可点击列表，HR 的请假及审批配置入口清晰；员工可读本人余额和流水。PC/H5 共用新审批与请假语义，旧记录可查看且不被新规则追溯扣款。

## 实施边界

正式客户规则未提供，本轮实现可配置机制和明确的演示默认值；不宣称合规额度、真实节假日配置或生产审批制度已确认。WeCom/OSS 真实联调、电子签章、公网部署及复杂流程设计器不纳入本轮。继续复用 Pure/Element Plus/Vant，保留 M4 分段、抽屉、时间线、浅深色和390px体验，不安装无关UI依赖。

后端先维护 `M5_API_CONTRACT.md` 并给出状态/并发/迁移约定，总控复核。后端独占 server/oa 和必要go.mod/go.sum；前端独占web-pure-admin/web；QA独占tests/scripts/deploy/Dockerfile/compose/.dockerignore及所有运行栈变更。总控负责其他docs、CI、最终commit/push。各方可阅读固定参考源码并记录路径/许可证/适配内容，不能把克隆当成功集成。

## 验收门槛

- 半天边界、非工作日、日期例外、跨年、多个年份余额不足、同人重叠、重复幂等与并发批准/撤回/撤销，不重复扣减或恢复。
- 年度台账人工基线与新流水可核对；规则和日历变更不改历史；旧 M1–M4 数据/附件完整。
- 规则优先级和回退、无效审批人/自审批、运行中与未来步骤交接、异常修复、催办限频/身份范围。
- 角色授权计数与列表一致，工资与私人表单不泄漏；PC/H5一致，未知写入正确重试或先读取核对。
- Go race/build、前端tests/typecheck/build、真实MySQL与浏览器、升级前后成对备份恢复，最终截图与源码/镜像绑定，main远端CI。
