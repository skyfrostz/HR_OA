# HR/OA 系统界面与任务流程改造

日期：2026-11-08。开始时 `main` 为 `3e11a2a4cf4efb46834fc0ad12ae3697a565a459`，工作树干净。当前运行 PC 为 Pure Admin / Vue 3 / Element Plus，H5 为 Vue 3 / Vant，服务端为 Go / Gin / MySQL。保留现有栈、品牌蓝、主题选择、权限、历史和业务状态机。

## 执行与所有权

用户明确要求所有前端修改由原前端会话统一处理。该会话负责共享 tokens、组件、布局、路由及全部业务页面；总控审核设计契约、协调接口、核对截图和最终集成。后端负责实际可证实的 API/权限/数据问题，QA 负责运行栈、基线与验收。两项临时前端子任务只读后停止，未写文件。

按仓库事实与基线 → 三个代表场景 → 全业务推广 → 集成验收的顺序执行，代表场景为员工列表/编辑、审批创建/处理、H5 长表单。不会仅交审查报告或首页样式。任何历史图问题先复现；当前已正确的项目记录为未复现。

| 假期与账目 | 可用突出，已用/预占可解释，年度与分页分开 | 服务端预占/扣减/释放/冲回与历史不变 |
| 规则 / 工作日历 | 条件、范围、优先级、状态结构化，紧凑有序步骤，分页归属明确 | 顺序审批非 BPMN；每周与日期例外，不虚构节假日 |
| 工作台 | 按角色显示真实待处理对象和明确空态 | 授权查询，不以当前页冒充全量，不填假趋势 |
| 通知 / 集成诊断 | 业务事件对象时间动作优先，诊断次级 | mock、API accepted、delivered、read不混同 |
| 全局状态 | 加载/失败/无权限/无结果与可恢复动作 | 不隐瞒请求失败、不伪造成功 |

## 验收规则

主要视口1440×900、1366×768、390×844，关键窄屏补320/360。前后图必须同角色、同数据、同状态、同视口、同主题。布局测量用内容或首字段位置及可达性解释，不把建议像素机械当成功标准。实际固定层按视口截图和滚动检查；不能仅依赖 fullPage 图或用 body overflow 隐藏问题。

覆盖空/单条/多条/多页，长中文/文件名/原因，1/10步审批，以及加载、失败、无权限、无结果。共享组件和核心路径覆盖浅深主题、实际对比度、键盘、焦点返回、标签和错误关联。真实设备软键盘未验证时必须注明，不等同于 Chromium 窄屏模拟通过。

功能验收覆盖员工编辑、合同生命周期、附件元数据/预览/下载/分类、导入、申请处理、假期账目、历史快照和通知深链。针对真实修改的日期/权限/并发/事务补测试；已有 build/typecheck/tests/lint 如实报告，禁止删规则或盲更测试掩盖失败。上游全树 lint 与本次变更范围区分，不无差别格式化未修改的上游代码。

不新增真实人员通知、客户 OSS 写入或生产部署。本轮合成数据、mock 和本机验收均不是客户服务验收。最终交付设计契约、变更与兼容说明、前后截图索引、验证证据及准确剩余项。
