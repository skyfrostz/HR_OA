# M2 界面设计基线

用户明确要求提高前端面板的视觉完成度；M2 同时交付 PC 人事界面升级和 H5 审批。保留 Vue 3 / Element Plus，H5 使用 Vant。不是复制完整第三方后台或引入第二套 PC 框架。

## 参考与取舍

- Pure Admin：https://github.com/pure-admin/vue-pure-admin 。主要参考清晰侧栏、浅灰工作区、白色内容面板及列表工具栏；现有 Element Plus 栈兼容。
- Vben Admin：https://github.com/vbenjs/vue-vben-admin 。参考工作台信息层次、用户区和统一组件尺寸。
- Soybean Admin：https://github.com/soybeanjs/soybean-admin 。补充参考轻量配色和留白；不迁移 Naive UI。
- 三者官方仓库当前标注 MIT。此轮为独立实现的视觉参考；如果复制代码或资产，必须额外记录路径和保留许可证。
- 不复制示例统计、装饰图表、无实际用途的菜单或不可用的搜索按钮。

## 统一视觉

- 克制、清晰的企业工作台。主色使用蓝色 #3563E9，正文深灰 #182238，次要文字 #667085，画布 #F5F7FB，面板白色，边框 #E7EBF2；语义颜色用于状态，不在普通按钮中混用。
- 系统中文字体，正文 14–15px、行高 1.5，标题 24–28px，辅助标签 12px；数字使用 tabular-nums。
- 间距使用 4/8/12/16/24/32，面板圆角 12px，输入与按钮高度至少 36px，移动端点击区域至少 44px。微弱阴影只用于浮层和选中层次。
- 使用现有图标资源的统一线性图标，禁止 emoji 充当导航图标；所有图标按钮有可访问名称。
- focus-visible 清楚，普通文字对比度至少 4.5:1；动画约 150ms 且尊重 reduced-motion。

## PC 可见改造（必须交付）

- 登录后建立约 220px 的深色侧栏、56–64px 白色顶栏和浅灰内容画布。侧栏含品牌、分组与真实入口：员工档案、移动审批；仅有两项也保持简洁，不增加空功能。
- 顶栏显示当前区域、真实用户和角色、退出操作；本地开发标识低调但清楚。窄屏改为紧凑顶部导航，不挤压表格。
- 员工档案页采用标题/说明/主操作区、紧凑的数据工具栏、列表和分页。可以展示接口 total，但不得把当前页数量当作全局统计；不增加后端不支持的全局搜索。
- 员工姓名/工号提供清楚的视觉层次和首字头像。表头浅灰、行 hover、数字对齐、操作位置固定，保留现有语义表格与标签。
- 详情页有返回入口、员工身份摘要和分组信息，减少大量垂直白色空卡；合同、附件保持操作就近和状态清楚。
- 登录页也需完成设计：明确的产品名、简短用途说明、整齐表单和本地开发提示；不用外部插图或虚构企业品牌。

## H5 审批（必须交付）

- 与 PC 共用色彩、字体和状态语义，布局使用移动端习惯。应用顶栏 + 清楚的分段标题 + 底部导航；宽屏展示居中移动工作区。
- 工作台有真实的发起入口、本人申请、待办、已办、通知。按角色/能力显示入口；无权页面不伪装为空数据。
- 请假、报销、通用申请使用独立可辨识图标和轻量色块。请求列表重点突出标题、类型、状态、申请时间，避免所有字段同权重。
- 详情使用状态摘要、表单字段、审批路径和历史时间线；当前任务的操作栏固定底部并留足内容空间。驳回和转交使用清楚的确认表单。
- 待办/空态/加载/失败/提交中/结果未知/已失效任务都有完整表现。结果未知保持原意图及幂等键，显式重试；样式不得破坏现有防重复逻辑。
- 通知区域明确标注“模拟通知”，不用产品界面展示内部事务/outbox 等实现术语。

## 验收

- 至少提供 PC 1440px 员工列表、详情，以及 H5 390px 工作台、任务详情截图。
- 没有溢出、遮挡、不可点击的底部按钮或新增空功能；登录、权限、敏感字段和既有 M1 操作全部回归。
- 视觉升级须实际出现在本地运行版本中，不能仅交付设计文档。
