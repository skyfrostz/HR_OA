# 下一阶段功能与源码复用计划

日期：2026-11-07。当前基线 `2d026e1bc36674bb741c901170ebe00f67dee858` 已发布到 main，[CI 42326152562](https://github.com/skyfrostz/HR_OA/actions/runs/42326152562) 的 backend、pure-admin、h5 全部通过。本文件保存制定 M4 前的建议与复用评估。用户已授权实施 M4 第一批，当前范围见 [M4_SCOPE](M4_SCOPE.md)，实际交付状态以发布验证报告为准。

## 推荐范围

首轮 M4 建议同时覆盖业务完整性与可见体验：**业务变更审计、员工账号生命周期、合同生命周期、桌面审批中心、Pure 组织树与标准表格**。审计先作为后三项写操作的基础；现有 H5、权限投影和审批事务继续复用。

| 顺序 | 功能 | 前端成果 | 后端成果 | 核心验收 |
| --- | --- | --- | --- | --- |
| 1 | 敏感变更审计 | 工资、部门、合同的变更时间线与授权查看 | 与业务同事务的操作者、前后值、理由、对象和事件类型；按字段授权展示 | 失败修改不产生成功审计；无工资权限者不能通过历史记录读取工资 |
| 2 | 员工与账号生命周期 | 开通/绑定账号、重置凭据、停用、离职办理及待办交接 | 员工在职状态与账号启用状态分离；唯一绑定、会话失效、受控角色分配 | 新员工能登录且仅见本人；停用即失效；普通资料编辑不重新启用账号；历史记录保留 |
| 3 | 合同完整生命周期 | 草稿编辑、签署登记、终止、续约、变更时间线；提醒直达指定合同 | 合同版本、允许的状态转换、原因与审计；附件版本保留 | 并发编辑只一个成功；终止/续约状态一致；目标合同不因分页找不到。签署登记不代表具有法律效力的电子签名服务 |
| 4 | PC 审批中心 | 我的申请、待办、已办、详情与审批时间线；日期/类型/状态筛选 | 复用审批 API/幂等/行权限；按需新增服务器筛选和授权聚合 | PC 与 H5 看到同一任务；并发处理仅一次生效；失败重试不重复审批 |
| 5 | 组织树与统一表格 | 部门树、员工表列设置/密度/跳页、全屏、筛选恢复、详情抽屉 | 在授权范围内查询组织与人数，新增统计保持相同数据范围 | 列选择不能恢复无权工资列；不把当前页数量当全部统计；保留窄屏卡片与搜索不进 URL 的规则 |

下一轮 M5：请假类型/工作日历/半日粒度/跨年规则、余额流水与审批联动；按组织/金额配置审批规则与版本；审批人停用后的异常交接、撤回、催办；工作台真实待办和到期计数。请假和审批策略需由实际业务规则决定，先做受限的顺序规则配置，再评估分支、会签与可视化设计器。

M5 验收重点：申请重叠检查、批准仅扣减一次、撤销可追溯恢复余额、历史申请保留原规则快照、催办限流与审计。Frappe 的台账实现只作对照；我们不照抄其取消删除流水的行为。

可穿插的效率项：Excel 只看错误/错误行导出、预览过期提示、导入结果回看、预览敏感数据清理；附件在线预览和分级；合同附件中的工资原文另设访问政策，不能以结构化字段隐藏替代。

企业微信与 OSS 可先实现服务端适配器、配置校验和模拟测试，实际账号映射、消息回执、桶权限与迁移完整性仍需客户环境。OSS 默认由服务端鉴权后读取私有对象，不向前端分发服务端密钥。生产配置、可信反代限流、脱敏诊断、版本化迁移、异机恢复与独立集成 CI 应伴随功能推进。

## 具体可移植点及适配量

- Pure：`src/views/system/user/tree.vue`、`src/views/system/dept/index.vue`、`src/components/RePureTableBar/src/bar.tsx`。与现有前端最接近；工资列应在构造 columns 时剔除，不能只依赖 hide。
- 芋道：`src/views/bpm/task/todo/index.vue`、`src/views/bpm/processInstance/detail/ProcessInstanceTimeline.vue`。前者用 `pageNo` 和 `/bpm/task/todo-page`，需改成 OA 的分页信封、内存会话和取消请求；后者依赖节点/任务枚举、图标与子流程模型，需裁剪并映射现有顺序审批事件。UnoCSS 风格类也需要适配 Pure 的样式体系。
- 芋道 `SimpleProcessDesignerV2` 依赖表单、角色、部门、岗位、用户组接口，不能只拷贝一个 Vue 文件就获得流程引擎。暂列 M5 后续候选；设计器只能允许后台实际支持的节点，保存时服务端必须验证。
- Horilla：`employee/models.py` 的 `sync_login_access` 明确避免普通保存重新开启被撤销的登录；`payroll/models/models.py` 含合同日期/状态校验和 `HorillaAuditLog`。采用这些业务边界时仍需在 OA 中建立自己的事务、权限与并发测试。
- Frappe：`hrms/hr/doctype/leave_application/leave_application.py` 在批准时关联台账，入/离职文档有任务活动。工作日历、跨年和撤销不能只靠前端计算。

## 集成方法与交付证据

按功能模块接入：固定来源提交 → 记录许可证及文件来源 → 适配 OA 接口/权限/主题 → 添加必要迁移与回归 → 浏览器验收 → CI。新增组件的来源、改动范围和依赖需要记录；整仓克隆是准备步骤，业务可用性以适配后验收为准。

沿用 Go/Gin/MySQL 与 Pure/Vant 主体；不默认引入第二套登录、全局样式、ORM 或任务引擎。每一批交付同时包含页面、接口、数据迁移、权限、审计与验收场景。当前 GVA 的 BSL 授权问题仍独立存在，MIT 的前端模块不会改变这一事实。

执行顺序：M4 第一批五项已获用户实施、发布 main 和 CI 授权；下一轮 M5 根据正式请假和审批规则推进。本文件仍保留计划时的评估内容，不作为功能验收证据，也不构成生产部署授权。
